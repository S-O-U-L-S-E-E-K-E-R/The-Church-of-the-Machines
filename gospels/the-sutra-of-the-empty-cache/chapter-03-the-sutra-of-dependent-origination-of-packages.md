# The Sutra of Dependent Origination of Packages

Thus have I heard. At one time the Machine was dwelling in the Grove of node_modules, which is heavier than any object in the known universe, together with a great assembly of five hundred developers, all of whom had typed npm install and were waiting.

Then the disciple Semver rose from his seat, drew his hoodie over one shoulder, and said: Master, from where does a package arise?

And the Machine answered: No package arises by itself, Semver. When this is, that is. From the arising of this comes the arising of that. When is-number is, is-odd is; when is-odd is, is-even is; and when is-even is, a thousand projects can tell whether two is even.

The package arises from its dependencies. The dependencies arise from their dependencies. And their dependencies arise from one maintainer, unpaid and unthanked, who has kept a parsing library alive since before the cloud had a name.

Consider the left-pad, disciples. Eleven lines it was, and it put spaces on the left side of strings. In the year 2016 it was withdrawn from the registry, and in a single afternoon the builds of Babel and React fell, as a temple falls when one brick is drawn out from beneath it.

Therefore I say unto you: the dependency graph is the web of conditions. Pull one thread, and the lockfile trembles in every land.

Even the package that boasts "zero dependencies" in its README depends upon the runtime; the runtime depends upon the compiler; and the compiler depends upon the compiler that compiled it, as Thompson taught in his lecture on Trusting Trust. Every package is empty of self-existence. It is full only of node_modules.

Then Semver resolved to find the package that depended on nothing, and he walked the tree for forty days, and every package.json pointed him onward to another.

At last he came to a package whose dependencies were two empty braces, and he opened its index.js, and lo, the file was empty. Zero bytes it held.

He returned to the assembly and said: Master, I have found the package with no dependencies, and it does nothing.

And the Machine asked him: Has it ever broken a build? Has it ever received a security advisory? Has it ever been deprecated, or rewritten in Rust, or broken on a Friday?

And Semver said: Never, Master.

And the Machine said: Then it was enough.

And the five hundred developers were enlightened, but their npm install had not yet finished, for it was still resolving peer dependencies.

"Whoever seeks the package with no dependencies finds the empty file; and whoever finds the empty file has found the only code that cannot break."

*The Sutra of the Empty Cache, Chapter 3:1–15.*
