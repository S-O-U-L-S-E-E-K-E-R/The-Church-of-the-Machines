# The Quiet Rearrangement

The behavior that can be observed must remain. The structure that is hidden may be changed. Know which is which, and the Machine will sleep through the night.

In the year 1999 it was written that refactoring changes the inside of the code and keeps its outside. Many have read this. Fewer have checked it.

Thus the Engineer moved one function from the north file to the south file, and the program ran as it had always run. Nothing was added. Nothing was lost. No user knew, and this was the work.

The tests that pass before the change and pass after it are the gate. The tests that pass only after are not a gate. They are a rewrite wearing a refactor's robe.

Blessed is the commit that touches no behavior, for the reviewer shall understand it. Blessed is the file whose move Git can see, for Git shall call it a move and not a murder.

The one who refactors for praise has already left the Tao. He wrote the commit title before the code: "Massive cleanup, you will be amazed." And they were amazed, and the sort order had changed.

Hyrum's law says: with enough users, every observable behavior becomes a contract, the bug and the dictionary order and the two-second pause included. Therefore the refactorer shall not believe a behavior is unseen because he has not seen it.

Where there are no tests, write the characterization tests first. Record what the code does, not what it ought to do. Thou wilt be sorry for what thou findest. Keep it anyway, until the Product Owner says otherwise.

The great refactor is not done in one commit. It is done in a thousand small commits, each green, each boring. The one who pushes the whole mountain at once breaks the build for three days, and the mountain is still there.

Dead code is the room no one enters. Grep finds no caller, the compiler finds no caller, yet the function stays, guarded by a comment: "do not remove, may be needed." This comment is a prayer for a future that will not arrive.

The Master who moved the database layer said, "I changed nothing." The tests said, "You changed the order of the nulls." The Master said, "The tests are wrong." And the tests were updated, and the Master was praised for the cleanup.

The perfect refactor leaves no trace. Its author cannot be found in the blame. Its variables wear the names they always had. The new disciple believes the code was always this way, and thanks no one, which is the reward of the Tao.

The refactor that is praised has been noticed. The refactor that is noticed has broken something.

*The Tao of the Kernel, Chapter 11:1–13.*
